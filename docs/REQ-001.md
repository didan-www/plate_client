# REQ-001 Qt 车牌识别管理客户端需求规格

| 属性 | 内容 |
| --- | --- |
| 文档编号 | REQ-001 |
| 文档版本 | 2.1 |
| 状态 | 已确认，待实现 |
| 日期 | 2026-08-11 |
| 目标平台 | Windows 10/11 64-bit |
| 技术基线 | C++17、Qt 6.11.1 Widgets、MinGW 64-bit |

## 1. 文档目的

本文档定义三端车牌识别教学系统中 Qt 管理客户端的业务范围、用户界面、Linux 服务端接口、本地数据边界和验收标准。

本文档是客户端需求的来源。软件架构和模块实现约束见 [REQ-001-design.md](REQ-001-design.md)。

## 2. 系统背景

系统由以下三部分组成：

| 系统 | 职责 |
| --- | --- |
| 嵌入式端 | 拍摄车辆照片并上传 Linux 服务端；接收服务端 MQTT 识别结果并控制抬杆 |
| Linux 服务端 | 保存图片、调用模型、记录 MySQL、发布识别事件和嵌入式结果 |
| Qt 管理端 | 登录、心跳、实时监控、历史查询、图片查看、CSV 下载和黑白名单管理 |

车牌识别由 Linux 服务端触发和执行。Qt 客户端不得上传图片给模型、调用识别接口或向嵌入式端发布放行结果。

## 3. 范围

### 3.1 首版包含

- 用户登录和注销。
- HTTP 服务状态和 MQTT 连接状态。
- HTTP 心跳。
- MQTT 实时识别事件订阅。
- 当前车辆图片、识别状态、结果和耗时展示。
- 本次登录期间最近 100 条实时记录。
- 服务端识别历史分页查询和设备筛选。
- 服务端 CSV 导出文件下载。
- 黑白名单查询、搜索、新增和删除。
- 7 天脱敏技术日志。

### 3.2 首版不包含

- Qt 客户端发起或执行车牌识别。
- Qt 客户端发布嵌入式识别或放行消息。
- SQLite、本地业务同步和直接 MySQL 连接。
- 车辆图片长期保存。
- 视频识别、摄像头识别和手动选图。
- 黑白名单参与放行决策。
- 名单变更 MQTT 推送。
- 角色权限、多语言、系统托盘和安装包。

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| `clientId` | 程序安装时配置的 Qt 管理端 UUID |
| `deviceId` | 嵌入式设备标识 |
| `recognitionId` | Linux 服务端生成的识别记录唯一标识 |
| `revision` | 同一识别记录的单调递增事件版本 |
| 实时记录 | 本次登录在线期间通过 MQTT 收到的识别快照 |
| 历史记录 | Linux 服务端从 MySQL 查询的识别日志 |
| HTTP 在线 | HTTP 服务可以建立连接并返回合法 HTTP 响应，不代表 MySQL 或模型健康 |

## 5. 技术与容量约束

- **NFR-001** 必须使用 C++17、Qt 6.11.1 Desktop MinGW 64-bit、MinGW-w64 GCC 13.1.0、CMake 和 Ninja。
- **NFR-002** Qt 模块为 Widgets、Network、Concurrent、Mqtt 和 Test，不使用 Qt Sql。
- **NFR-003** Qt MQTT 使用与 Qt 精确匹配的 `v6.11.1`，构建到项目本地依赖目录。
- **NFR-004** 教学环境规模为 1 至 10 台嵌入式设备，总照片峰值不超过每秒 1 张。
- **NFR-005** UI 支持 1366x768 至 4K 和 Windows 100%-200% DPI。
- **NFR-006** 首版界面和 CSV 使用简体中文。
- **NFR-007** 业务时间使用 ISO 8601 北京时间 `+08:00`。

## 6. 总体通信流程

1. Qt 加载本地引导配置并显示登录页。
2. 用户通过 Linux HTTP 服务登录。
3. 登录响应返回访问令牌、到期时间、MQTT 地址、凭据和管理事件主题。
4. Qt 进入主界面，启动 HTTP 心跳并异步连接 MQTT。
5. Linux 服务端保存车辆图片并提交 MySQL 后，发布 `PROCESSING` 完整快照。
6. Qt 根据 `recognitionId` 下载图片并显示“识别中”。
7. Linux 服务端完成模型识别并更新 MySQL 后，发布 `SUCCEEDED` 或 `FAILED` 完整快照。
8. Qt 更新当前车辆和实时结果列表。
9. 历史页面和名单页面按用户操作调用 HTTP API。

## 7. 功能需求

### 7.1 启动和配置

- **FR-001** 程序旁必须存在 `config/client.json`，只允许 `clientId`、`loginBaseUrl` 和 `allowInsecureTransport`；任何未知字段均视为非法配置。
- **FR-002** `clientId` 必须是 UUID；`loginBaseUrl` 必须是合法 HTTP/HTTPS 基址，可包含路径前缀，但不得包含查询参数、片段或用户信息。
- **FR-003** 配置非法时显示阻断错误，不进入登录流程，不使用隐式服务器地址。
- **FR-004** `allowInsecureTransport` 缺省为 `false`，为 `false` 时拒绝明文 HTTP/MQTT。
- **FR-005** 版本和构建日期由 CMake 注入并只读显示。

### 7.2 登录和会话

- **FR-010** 登录页依次显示“车牌识别系统”、用户名、密码和登录按钮。
- **FR-011** 密码掩码显示，回车可提交，提交期间禁止重复请求。
- **FR-012** 只记住用户名，不保存密码、访问令牌或 MQTT 凭据。
- **FR-013** 登录使用单访问令牌，不使用刷新令牌。
- **FR-014** 访问令牌和 MQTT 凭据必须具有相同到期时间。
- **FR-015** 登录成功后立即进入主界面，不等待 MQTT 连接。
- **FR-016** 到期或任何业务接口返回 HTTP 401 时停止心跳、断开 MQTT、清理会话并返回登录页。
- **FR-017** 每次登录建立新的会话代次，旧会话响应不得更新新会话 UI。

### 7.3 HTTP 服务状态

- **FR-020** 主界面左侧底部独立显示 `HTTP服务` 状态。
- **FR-021** 状态值为“检测中”“在线”“异常”。
- **FR-022** 登录成功后、首次心跳完成前显示“检测中”。
- **FR-023** 心跳每 30 秒发送一次，单次超时 5 秒。
- **FR-024** 任意请求收到合法 HTTP 响应时可恢复为“在线”，并清零连续心跳连接失败计数。
- **FR-025** 连续 3 次心跳连接失败或超时后显示“异常”。
- **FR-026** 收到合法 HTTP 响应表示服务可访问；业务 4xx/5xx 在对应页面处理，不代表网络不可达。
- **FR-027** HTTP 状态只表示网络可访问性，不反映 MySQL 或模型健康。
- **FR-028** HTTP 状态异常时不预先禁用查询、导出或名单操作，实际结果由请求响应决定。

### 7.4 MQTT 状态与事件

- **FR-030** 主界面独立显示 MQTT“未连接”“重连中”“已连接”。
- **FR-031** MQTT 使用 3.1.1、QoS 1、非 retain、`cleanSession=true`。
- **FR-032** 所有管理客户端订阅普通管理事件主题，不使用共享订阅。
- **FR-033** MQTT 发生网络中断或 Broker 暂不可用等暂时错误时，按 1、2、4 秒递增到 60 秒上限持续重连。
- **FR-034** 每条 MQTT 事件必须是完整识别记录快照。
- **FR-035** 客户端按 `recognitionId + revision` 去重；相同或较低 revision 不得回退状态。
- **FR-036** 缺少必填字段、字段类型错误或 schema 版本不支持的消息只写技术日志并丢弃。
- **FR-037** MQTT 重连后只校准当前仍显示 `PROCESSING` 的 `recognitionId`，不自动加载其他历史。
- **FR-038** MQTT 用户名或密码错误、无权限、Client ID 被拒绝、协议不支持、订阅失败或 TLS 证书错误属于永久错误；当前会话必须停止自动重连。
- **FR-039** MQTT 永久错误不强制退出 HTTP 会话。主界面和 HTTP 功能继续可用，MQTT 显示“未连接”及“配置或授权错误”原因；只有建立新的登录会话后才允许再次连接。

### 7.5 实时监控

- **FR-040** 左侧菜单名称为“实时监控”。
- **FR-041** 当前车辆跟随最新收到的 `PROCESSING` 事件。
- **FR-042** 旧车辆完成事件只更新实时列表，不抢占当前图片区。
- **FR-043** 当前车辆图片通过固定的识别记录图片接口下载，不接受事件提供的任意 URL。
- **FR-044** 图片只保存在内存，保持宽高比，不启用磁盘缓存。
- **FR-045** 图片下载发生连接失败、30 秒超时或可重试 5xx 时自动重试 2 次，等待 1 秒和 3 秒；4xx、内容类型错误、超限或解码失败不自动重试；最终失败显示占位和手动重试按钮。
- **FR-046** 图片重试不得阻塞 MQTT 结果更新。
- **FR-047** 旧图片请求晚于新请求完成时，不得覆盖新车辆图片。
- **FR-048** `PROCESSING` 显示“识别中”，`SUCCEEDED` 和 `FAILED` 显示“已识别完成”。
- **FR-049** 成功显示车牌号；失败显示错误码和错误信息。
- **FR-050** 实时列表仅保存本次登录期间最近 100 条记录。
- **FR-051** 实时列表列为序号、设备、车牌号、状态和时间，成功与失败均展示。
- **FR-052** MQTT 重连后当前记录查询到最终状态时，更新当前面板和实时列表。
- **FR-053** 图片压缩响应不得超过 20 MB，宽和高分别不得超过 8192 像素，总像素不得超过 4000 万；任一检查失败均按图片加载失败处理。
- **FR-054** 图片尺寸预检和 `QImage` 解码必须在线程池执行；`QPixmap` 只能在 UI 线程创建并设置到 QWidget。

### 7.6 历史日志和导出

- **FR-060** 历史数据通过 HTTP 从 Linux 服务端 MySQL 查询，客户端不保存业务副本。
- **FR-061** 默认查询北京时间当天，支持起止时间和可选 `deviceId`。
- **FR-062** 每页 100 条，显示总数和上一页/下一页。
- **FR-063** 表格至少显示记录 ID、设备、车牌号、状态、错误、拍摄时间、开始时间、完成时间和耗时。
- **FR-064** 快速筛选、翻页时，旧请求响应不得覆盖当前条件结果。
- **FR-065** CSV 由 Linux 服务端基于当前筛选条件直接生成。
- **FR-066** Qt 只负责异步下载 CSV，并使用保存对话框和 `QSaveFile` 原子落盘。
- **FR-067** 取消、失败或会话失效时不得留下不完整目标文件。

### 7.7 黑白名单管理

- **FR-070** 左侧菜单增加“黑白名单管理”。
- **FR-071** 页面包含“白名单”和“黑名单”两个标签页。
- **FR-072** 每个标签页支持车牌搜索、重置、刷新、新增、删除和分页。
- **FR-073** 搜索只对车牌号执行包含匹配，按回车或搜索按钮触发。
- **FR-074** 每页 100 条，按创建时间倒序。
- **FR-075** 表格列为序号、车牌号、备注、创建用户和创建时间。
- **FR-076** 所有已登录用户均可查询、新增和删除，不引入角色权限。
- **FR-077** 新增字段为车牌号和可选备注，名单类型继承当前标签页。
- **FR-078** 车牌基础规范化为去除首尾空白、英文字母转大写、拒绝内部空白、长度 1 至 16。
- **FR-079** 客户端和服务端均执行基础校验，服务端校验为最终依据。
- **FR-080** 同一规范化车牌不能同时存在于黑名单和白名单，也不能在同一名单重复。
- **FR-081** 删除前显示包含车牌号和名单类型的确认对话框。
- **FR-082** 增删成功后重新查询当前页，不做乐观本地修改。
- **FR-083** 新增或删除请求超时后，按规范化车牌精确查询服务器现状，再判断是否生效。
- **FR-084** 无法核实写入结果时显示“操作结果无法确认”，保留原表格。
- **FR-085** 多管理端名单变更不实时推送；进入页面、搜索、翻页、操作成功和手动刷新时查询。
- **FR-086** 首版不支持编辑、批量删除、有效期、车主字段或自动跨名单转移。
- **FR-087** 黑白名单本期只作为配置数据，不参与抬杆决策。

### 7.8 导航和退出

- **FR-090** 主界面使用左侧导航和右侧页面，登录后 `showMaximized()`。
- **FR-091** 左侧依次显示实时监控、置灰的视频识别、置灰的摄像头识别、日志记录、黑白名单管理。
- **FR-092** 左侧底部显示默认头像、用户名、退出登录、HTTP 状态、MQTT 状态、版本和构建日期。
- **FR-093** 点击退出登录时取消网络请求、停止心跳、断开 MQTT、清理内存数据并返回登录页。
- **FR-094** 关闭窗口执行相同清理后退出，不最小化到托盘。
- **FR-095** 退出后的网络回调不得更新登录页或已销毁主窗口。

## 8. HTTP 接口契约

### 8.1 统一信封

除图片和 CSV 二进制响应外，请求和响应均使用 UTF-8 JSON，响应 `Content-Type` 为 `application/json`。客户端接受的单个 JSON 响应体上限为 2 MB；有 `Content-Length` 时先行检查，接收过程中按解码后的累计响应体字节数再次检查，超限立即终止请求。

JSON 响应统一使用以下信封，所有字段必须存在且类型固定：

```json
{
  "success": true,
  "code": "OK",
  "message": "",
  "requestId": "request-uuid",
  "data": {}
}
```

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `success` | boolean | 否 | 成功为 `true`，失败为 `false` |
| `code` | string | 否 | 稳定的业务结果码 |
| `message` | string | 否 | 可展示信息；无内容时为空字符串 |
| `requestId` | string | 否 | 服务端生成的请求追踪标识 |
| `data` | object/null | 是 | 成功时按接口返回指定 DTO；无返回数据或失败时为 `null` |

HTTP 成功状态必须同时满足 2xx、`success=true` 和符合对应 DTO 的 `data`。HTTP 错误状态使用 `success=false` 且 `data=null`；客户端不得只依据 HTTP 状态或 `success` 单项判定成功。

### 8.2 登录

`POST /api/v1/auth/login`

请求 DTO：

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `username` | string | 否 | 不得为空 |
| `password` | string | 否 | 不得为空 |
| `clientId` | string | 否 | UUID 字符串 |

成功响应的 `data` 必须精确包含以下字段，字段均不可为空：

```json
{
  "displayName": "操作员",
  "accessToken": "access-token",
  "expiresAt": "2026-08-11T18:00:00+08:00",
  "mqtt": {
    "host": "127.0.0.1",
    "port": 8883,
    "tls": true,
    "username": "mqtt-user",
    "password": "mqtt-password",
    "expiresAt": "2026-08-11T18:00:00+08:00",
    "eventTopic": "plate/management/recognition-events"
  }
}
```

字段类型为：`displayName`、`accessToken`、`expiresAt`、`mqtt.host`、`mqtt.username`、`mqtt.password`、`mqtt.expiresAt` 和 `mqtt.eventTopic` 是 string，`mqtt.port` 是 1 至 65535 的 integer，`mqtt.tls` 是 boolean。两个 `expiresAt` 必须是同一 ISO 8601 北京时间值。

### 8.3 心跳和注销

- `POST /api/v1/clients/heartbeat`：Bearer Token；统一信封只用于响应，请求体为 `{ "clientId": string, "appVersion": string }`，两个字段均必填且不可为空；成功响应的信封 `data=null`。
- `POST /api/v1/auth/logout`：Bearer Token；成功响应的信封 `data=null`；网络失败或超时时允许客户端完成本地退出。

### 8.4 识别记录

- `GET /api/v1/recognitions/{recognitionId}`：查询单条记录，用于 MQTT 重连后的当前记录校准；成功响应 `data` 为一个 `RecognitionSnapshot`。
- `GET /api/v1/recognitions/{recognitionId}/image`：下载 JPEG/PNG 图片。
- `GET /api/v1/recognitions`：参数为 string 类型的 `startTime`、`endTime`、可选 `deviceId`，以及 integer 类型的 `page`、`pageSize`；成功响应 `data` 为 `PageResult<RecognitionSnapshot>`。
- `GET /api/v1/recognitions/export`：使用相同筛选条件，返回 UTF-8 BOM CSV。

`RecognitionSnapshot` 与 MQTT 事件使用相同 DTO，字段定义如下：

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `schemaVersion` | integer | 否 | 首版固定为 1 |
| `recognitionId` | string | 否 | 识别记录唯一标识 |
| `revision` | integer | 否 | 64 位正整数，同一记录单调递增 |
| `deviceId` | string | 否 | 不得为空 |
| `status` | string | 否 | `PROCESSING`、`SUCCEEDED` 或 `FAILED` |
| `plateNumber` | string/null | 是 | 非空时为规范化车牌，长度 1 至 16 个字符 |
| `errorCode` | string/null | 是 | 稳定错误码 |
| `errorMessage` | string/null | 是 | 最多 512 个字符 |
| `capturedAt` | string | 否 | ISO 8601 北京时间 |
| `startedAt` | string | 否 | ISO 8601 北京时间 |
| `completedAt` | string/null | 是 | ISO 8601 北京时间 |
| `durationMs` | integer/null | 是 | 64 位非负整数，单位毫秒 |

以上字段均必须存在；标记为可空的字段在无值时必须显式为 JSON `null`，不得省略。`recognitionId`、`deviceId` 以及非空状态下的 `plateNumber`、`errorCode`、`errorMessage` 不得是空字符串。

状态与可空字段必须满足：

| 状态 | `plateNumber` | `errorCode` / `errorMessage` | `completedAt` / `durationMs` |
| --- | --- | --- | --- |
| `PROCESSING` | `null` | 均为 `null` | 均为 `null` |
| `SUCCEEDED` | 非空 | 均为 `null` | 均非空 |
| `FAILED` | `null` | 均非空 | 均非空 |

分页 DTO 固定为：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 100,
  "total": 0
}
```

`items` 是对应 DTO 数组，`page` 是从 1 开始的 integer，`pageSize` 首版固定为 100，`total` 是 64 位非负 integer。

图片响应只接受 `image/jpeg` 或 `image/png`，压缩响应体最大接受 20 MB。客户端必须在后台线程通过 `QImageReader::size()` 预检宽高，要求宽和高分别不超过 8192 像素且乘积不超过 4000 万；解码为 `QImage` 后必须再次校验实际尺寸。`QPixmap` 只能在 UI 线程创建。

CSV 的 `Content-Type` 为 `text/csv; charset=utf-8`，文件必须带 UTF-8 BOM，首行列名和顺序固定为：`记录ID,设备,车牌号,状态,错误码,错误信息,拍摄时间,开始时间,完成时间,耗时(ms)`。CSV 采用流式下载，不受 2 MB JSON 响应上限约束。

### 8.5 黑白名单

- `GET /api/v1/access-lists?listType=WHITE&keyword=&page=1&pageSize=100`：成功响应 `data` 为 `PageResult<AccessListRecord>`。
- `GET /api/v1/access-lists/lookup?plateNumber=...`：找到时 `data` 为一个 `AccessListRecord`，未找到时返回 HTTP 404。
- `POST /api/v1/access-lists`：成功响应 `data` 为新建的完整 `AccessListRecord`。
- `DELETE /api/v1/access-lists/{id}`：`id` 是 64 位正整数，成功响应 `data=null`。

新增请求：

```json
{
  "listType": "WHITE",
  "plateNumber": "京A12345",
  "remark": "教学测试车辆"
}
```

名单记录：

```json
{
  "id": 1,
  "listType": "WHITE",
  "plateNumber": "京A12345",
  "remark": "教学测试车辆",
  "createdBy": "operator",
  "createdAt": "2026-08-11T11:00:00+08:00"
}
```

`AccessListRecord` 字段规则如下：

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `id` | integer | 否 | 64 位正整数 |
| `listType` | string | 否 | `WHITE` 或 `BLACK` |
| `plateNumber` | string | 否 | 规范化车牌，长度 1 至 16 个字符 |
| `remark` | string | 否 | 可为空字符串，最多 200 个字符，不使用 `null` |
| `createdBy` | string | 否 | 创建用户显示值 |
| `createdAt` | string | 否 | ISO 8601 北京时间 |

以上字段均必须存在。新增请求中的 `remark` 字段也必须存在，用户未填写时发送空字符串。

同一规范化车牌冲突返回 HTTP 409；记录不存在返回 HTTP 404；权限或会话问题返回 HTTP 401/403。

### 8.6 HTTP 超时和重试

超时从请求发出时开始计算，到完整响应体接收完成为止。每个请求必须使用独立总时限定时器，超时后中止对应 `QNetworkReply`。

| 请求 | 总时限 | 自动重试策略 |
| --- | ---: | --- |
| 登录 | 10 秒 | 不重试，由用户重新提交 |
| 注销 | 5 秒 | 不重试，超时后继续本地退出 |
| 心跳 | 5 秒 | 不立即重试，等待下一个 30 秒周期 |
| 识别详情、历史、名单分页和精确查询 | 10 秒 | 不重试，由用户重试；重连校准按下述规则处理 |
| 图片下载 | 30 秒 | 连接失败、超时或可重试 5xx 时，等待 1 秒和 3 秒重试，共最多 3 次请求 |
| 名单新增、删除 | 10 秒 | 不重复写入；超时后使用精确查询核实服务器状态 |
| CSV 下载 | 120 秒 | 不重试，由用户重新导出 |

MQTT 重连后的当前记录校准失败时保留现状；HTTP 状态以后从“异常”恢复为“在线”时，如果当前记录仍为 `PROCESSING`，只补偿查询一次。除图片下载外，不得对 GET 请求执行隐式循环重试。

## 9. MQTT 事件契约

管理事件主题由登录响应下发，Mock 默认使用 `plate/management/recognition-events`。

事件示例：

```json
{
  "schemaVersion": 1,
  "recognitionId": "recognition-uuid",
  "revision": 1,
  "deviceId": "device-001",
  "status": "PROCESSING",
  "plateNumber": null,
  "errorCode": null,
  "errorMessage": null,
  "capturedAt": "2026-08-11T11:00:00+08:00",
  "startedAt": "2026-08-11T11:00:01+08:00",
  "completedAt": null,
  "durationMs": null
}
```

- 第一次事件为 `PROCESSING`。
- 最终事件为 `SUCCEEDED` 或 `FAILED`，并使用更高 revision。
- 成功填写 `plateNumber`；失败填写稳定 `errorCode` 和可读 `errorMessage`。
- 最终事件仍携带全部字段，不依赖此前事件。
- MQTT 只有在 TCP/TLS 连接、MQTT CONNECT 和主题订阅全部成功后才进入“已连接”。
- 网络中断和 Broker 暂不可用属于暂时错误，按 FR-033 重连。
- 用户名或密码错误、无权限、Client ID 被拒绝、协议不支持、订阅失败和 TLS 证书错误属于永久错误，按 FR-038 至 FR-039 停止当前会话的自动重连并显示原因。

## 10. 本地数据和日志

- 引导配置位于程序旁 `config/client.json`。
- 上次用户名使用 `QSettings`。
- 技术日志位于 `QStandardPaths::AppLocalDataLocation/logs`。
- 技术日志按日生成，保留 7 天，启动时清理过期文件。
- 日志不得包含密码、令牌、MQTT 密码、Authorization 头或完整敏感响应。
- 不创建 SQLite 数据库，不直接连接 MySQL，不保存车辆图片或业务历史。

## 11. 异步和安全要求

- **NFR-010** 所有 HTTP/MQTT 操作必须异步。
- **NFR-011** 每次登录使用会话代次，每次页面查询使用请求代次。
- **NFR-012** 响应只有在会话、页面条件和业务对象仍匹配时才能更新 UI。
- **NFR-013** 图片尺寸预检和 `QImage` 解码必须在线程池执行，CSV 文件收尾不得长时间阻塞 UI；`QPixmap` 和 QWidget 只能在 UI 线程访问。
- **NFR-014** 密码、访问令牌和 MQTT 凭据只驻留内存。
- **NFR-015** 不得静默忽略 TLS 证书错误。
- **NFR-016** 单个 JSON 响应体最大 2 MB，图片压缩响应体最大 20 MB，图片宽高分别最大 8192 像素且总像素最大 4000 万；名单备注最大 200 个字符，识别错误信息最大 512 个字符。

## 12. 已确认限制

- 实时首页不是历史数据来源，只显示本次登录期间事件。
- MQTT 重连只校准当前 `PROCESSING` 记录，不补齐其他事件。
- 完整记录需要用户进入日志页查询。
- HTTP 状态只表示网络可访问。
- 名单变更不实时同步到其他 Qt 客户端。
- 名单不参与当前抬杆规则。
