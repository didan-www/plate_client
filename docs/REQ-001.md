## 1. 文档目的

本文档定义三端车牌识别教学系统中 Qt 管理客户端的业务范围、用户界面、Linux 服务端接口、本地数据边界和验收标准。

本文档是客户端需求的来源。软件架构和模块实现约束见 [REQ-001-design.md](REQ-001-design.md)。

## 2. 系统背景

系统由以下三部分组成：

| 系统 | 职责 |
| --- | --- |
| 嵌入式端 | 拍摄车辆照片并上传 Linux 服务端；接收服务端 MQTT 识别结果并控制抬杆 |
| Linux 服务端 | 保存图片、调用模型、记录 MySQL、发布识别事件和嵌入式结果 |
| Qt 管理端 | 登录、心跳、实时监控、历史查询、图片查看、CSV 下载和黑白名单管理 |

车牌识别由 Linux 服务端触发和执行。Qt 客户端不得上传图片给模型、调用识别接口或向嵌入式端发布放行结果。

## 3. 范围

### 3.1 首版包含

- 用户登录和注销。
- HTTP 服务状态和 MQTT 连接状态。
- HTTP 心跳。
- MQTT 实时识别事件订阅。
- 当前车辆图片、识别状态、结果和耗时展示。
- 本次登录期间最近 100 条实时记录。
- 服务端识别历史分页查询和设备筛选。
- 服务端 CSV 导出文件下载。
- 黑白名单查询、搜索、新增和删除。
- 7 天脱敏技术日志。

### 3.2 首版不包含

- Qt 客户端发起或执行车牌识别。
- Qt 客户端发布嵌入式识别或放行消息。
- SQLite、本地业务同步和直接 MySQL 连接。
- 车辆图片长期保存。
- 视频识别、摄像头识别和手动选图。
- 黑白名单参与放行决策。
- 名单变更 MQTT 推送。
- 角色权限、多语言、系统托盘和安装包。

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| `clientId` | 程序安装时配置的 Qt 管理端 UUID |
| `deviceId` | 嵌入式设备标识 |
| `recognitionId` | Linux 服务端生成的识别记录唯一标识 |
| `revision` | 同一识别记录的单调递增事件版本 |
| 实时记录 | 本次登录在线期间通过 MQTT 收到的识别快照 |
| 历史记录 | Linux 服务端从 MySQL 查询的识别日志 |
| HTTP 在线 | HTTP 服务可以建立连接并返回合法 HTTP 响应，不代表 MySQL 或模型健康 |

## 5. 技术与容量约束

- **NFR-001** 必须使用 C++17、Qt 6.11.1 Desktop MinGW 64-bit、MinGW-w64 GCC 13.1.0、CMake 和 Ninja。
- **NFR-002** Qt 模块为 Widgets、Network、Concurrent、Mqtt 和 Test，不使用 Qt Sql。
- **NFR-003** Qt MQTT 使用与 Qt 精确匹配的 `v6.11.1`，构建到项目本地依赖目录。
- **NFR-004** 教学环境规模为 1 至 10 台嵌入式设备，总照片峰值不超过每秒 1 张。
- **NFR-005** UI 支持 1366x768 至 4K 和 Windows 100%-200% DPI。
- **NFR-006** 首版界面和 CSV 使用简体中文。
- **NFR-007** 业务时间使用 ISO 8601 北京时间 `+08:00`。

## 6. 总体通信流程

1. Qt 加载本地引导配置并显示登录页。
2. 用户通过 Linux HTTP 服务登录。
3. 登录响应返回访问令牌、到期时间、MQTT 地址、凭据和管理事件主题。
4. Qt 进入主界面，启动 HTTP 心跳并异步连接 MQTT。
5. Linux 服务端保存车辆图片并提交 MySQL 后，发布 `PROCESSING` 完整快照。
6. Qt 根据 `recognitionId` 下载图片并显示“识别中”。
7. Linux 服务端完成模型识别并更新 MySQL 后，发布 `SUCCEEDED` 或 `FAILED` 完整快照。
8. Qt 更新当前车辆和实时结果列表。
9. 历史页面和名单页面按用户操作调用 HTTP API。

## 7. 功能需求

### 7.1 启动和配置

- **FR-001** 程序旁必须存在 `config/client.json`，只允许 `clientId`、`loginBaseUrl` 和 `allowInsecureTransport`；任何未知字段均视为非法配置。
- **FR-002** `clientId` 必须是 UUID；`loginBaseUrl` 必须是合法 HTTP/HTTPS 基址，可包含路径前缀，但不得包含查询参数、片段或用户信息。
- **FR-003** 配置非法时显示阻断错误，不进入登录流程，不使用隐式服务器地址。
- **FR-004** `allowInsecureTransport` 缺省为 `false`，为 `false` 时拒绝明文 HTTP/MQTT。
- **FR-005** 版本和构建日期由 CMake 注入并只读显示。

### 7.2 登录和会话

- **FR-010** 登录页使用固定 `520×420` 逻辑尺寸和 `44px` 工业蓝自绘标题栏；页面依次显示居中的 Logo 与“车牌识别系统”、左对齐的用户名/密码图标表单和靠下居中的登录按钮。
- **FR-011** 密码掩码显示，回车可提交，提交期间禁止重复请求。
- **FR-012** 只记住用户名，不保存密码、访问令牌或 MQTT 凭据。
- **FR-013** 登录使用单访问令牌，不使用刷新令牌。
- **FR-014** 访问令牌和 MQTT 凭据必须具有相同到期时间。
- **FR-015** 登录成功后立即进入主界面，不等待 MQTT 连接。
- **FR-016** 到期或任何业务接口返回 HTTP 401 时停止心跳、断开 MQTT、清理会话并返回登录页。
- **FR-017** 每次登录建立新的会话代次，旧会话响应不得更新新会话 UI。

`SessionService` 是访问令牌和 MQTT 凭据的唯一长期持有者。登录成功时认证层直接移交完整会话，调用方只获得显示名、到期时间和正数 `sessionGeneration`；基础设施只能按当前代次临时使用凭据，UI 不得读取凭据。

开发任务边界上，TASK-008 登录成功后通过可替换窗口工厂立即创建最小承接窗口，以独立验证“不等待 MQTT”；TASK-009 必须将默认工厂替换为正式 `MainWindow`。最小承接窗口不是首版最终主界面，不得提前包含导航、连接状态或业务页面。

### 7.3 HTTP 服务状态

- **FR-020** 主界面左侧底部独立显示 `HTTP服务` 状态。
- **FR-021** 状态值为“检测中”“在线”“异常”。
- **FR-022** 登录成功后、首次心跳完成前显示“检测中”。
- **FR-023** 心跳每 30 秒发送一次，单次超时 5 秒。
- **FR-024** 任意请求收到合法 HTTP 响应时可恢复为“在线”，并清零连续心跳连接失败计数。
- **FR-025** 连续 3 次心跳连接失败或超时后显示“异常”。
- **FR-026** 收到合法 HTTP 响应表示服务可访问；业务 4xx/5xx 在对应页面处理，不代表网络不可达。
- **FR-027** HTTP 状态只表示网络可访问性，不反映 MySQL 或模型健康。
- **FR-028** HTTP 状态异常时不预先禁用查询、导出或名单操作，实际结果由请求响应决定。

### 7.4 MQTT 状态与事件

- **FR-030** 主界面独立显示 MQTT“未连接”“重连中”“已连接”。
- **FR-031** MQTT 使用 3.1.1、QoS 1、非 retain、`cleanSession=true`。
- **FR-032** 所有管理客户端订阅普通管理事件主题，不使用共享订阅。
- **FR-033** MQTT 发生网络中断或 Broker 暂不可用等暂时错误时，按 1、2、4 秒递增到 60 秒上限持续重连。
- **FR-034** 每条 MQTT 事件必须是完整识别记录快照。
- **FR-035** 客户端按 `recognitionId + revision` 去重；相同或较低 revision 不得回退状态。
- **FR-036** 缺少必填字段、字段类型错误或 schema 版本不支持的消息只写技术日志并丢弃。
- **FR-037** MQTT 重连后只校准当前仍显示 `PROCESSING` 的 `recognitionId`，不自动加载其他历史。
- **FR-038** MQTT 用户名或密码错误、无权限、Client ID 被拒绝、协议不支持、订阅失败或 TLS 证书错误属于永久错误；当前会话必须停止自动重连。
- **FR-039** MQTT 永久错误不强制退出 HTTP 会话。主界面和 HTTP 功能继续可用，MQTT 显示“未连接”及“配置或授权错误”原因；只有建立新的登录会话后才允许再次连接。

### 7.5 实时监控

- **FR-040** 左侧菜单名称为“实时监控”。
- **FR-041** 当前车辆跟随最新收到的 `PROCESSING` 事件。
- **FR-042** 旧车辆完成事件只更新实时列表，不抢占当前图片区。
- **FR-043** 当前车辆图片通过固定的识别记录图片接口下载，不接受事件提供的任意 URL。
- **FR-044** 图片只保存在内存，保持宽高比；每次图片请求必须强制从网络获取并禁止保存网络缓存，不创建或使用磁盘网络缓存。
- **FR-045** 图片下载发生连接失败、单次请求 30 秒总时限到期，或 HTTP 500、502、503、504 时自动重试 2 次，等待 1 秒和 3 秒；其他 5xx、4xx、TLS 错误、内容类型错误、超限、协议错误或解码失败不自动重试。最终失败显示占位和手动重试按钮；手动重试建立新的逻辑图片请求系列，并重新获得立即请求、等待 1 秒和等待 3 秒的最多 3 次机会。
- **FR-046** 图片重试不得阻塞 MQTT 结果更新。
- **FR-047** 旧图片请求晚于新请求完成时，不得覆盖新车辆图片。
- **FR-048** `PROCESSING` 显示“识别中”，`SUCCEEDED` 和 `FAILED` 显示“已识别完成”。
- **FR-049** 成功显示车牌号；识别结果符合“省份简称 + ASCII 大写城市字母 + 后续字符”时，仅在界面显示层于前两个字符后插入 `·`（例如协议值 `陕U806RG` 显示为 `陕U·806RG`），不得修改 DTO、查询、名单或 CSV 中的规范化值；失败显示错误码和错误信息。
- **FR-050** 实时列表仅保存本次登录期间最近 100 条记录。
- **FR-051** 实时列表列为序号、设备、车牌号、状态和时间，成功与失败均展示。
- **FR-052** MQTT 重连后当前记录查询到最终状态时，更新当前面板和实时列表。
- **FR-053** 图片压缩响应不得超过 20 MiB，宽和高分别不得超过 8192 像素，总像素不得超过 4000 万；任一检查失败均按图片加载失败处理。
- **FR-054** 图片尺寸预检和 `QImage` 解码必须在线程池执行；`QPixmap` 只能在 UI 线程创建并设置到 QWidget。

### 7.6 历史日志和导出

- **FR-060** 历史数据通过 HTTP 从 Linux 服务端 MySQL 查询，客户端不保存业务副本。
- **FR-061** 历史筛选时间固定使用 `+08:00`，按 `[startTime, endTime)` 半开区间查询；默认范围为当前北京时间当天 `00:00:00+08:00` 至次日 `00:00:00+08:00`。支持可选 `deviceId` 自由文本筛选，提交时去除首尾空白，结果为空则省略该参数。
- **FR-062** 每页固定 100 条，显示总数和上一页/下一页；响应 `page` 必须等于请求 `page`，否则按协议错误处理并保留当前结果。
- **FR-063** 表格固定显示十列：记录 ID、设备、车牌号、状态、错误码、错误信息、拍摄时间、开始时间、完成时间和耗时。
- **FR-064** 搜索和重置均回到第一页，重置后立即查询默认北京时间当天；翻页只使用最后已提交的筛选，未搜索的编辑值不生效。历史页首次显示以及每次切离后重新显示时查询或刷新最后已提交条件；快速筛选、翻页或重新显示时，旧请求响应不得覆盖当前条件结果。
- **FR-065** CSV 由 Linux 服务端基于历史页最后已提交的 `startTime`、`endTime` 和可选 `deviceId` 筛选快照直接生成；导出请求忽略分页的 `page`、`pageSize` 和控件中尚未搜索的编辑值，不使用当前表格拼装 CSV。
- **FR-066** `HistoryPage` 显示保存对话框，默认文件名为 `车牌识别记录_yyyyMMdd_HHmmss.csv` 并使用默认 `csv` 后缀；取消保存对话框不得发起网络请求。确认目标路径后，Qt 只负责异步下载 CSV，并使用禁用 direct-write fallback 的 `QSaveFile` 原子落盘。
- **FR-067** 同一时刻只允许一个 CSV 导出；下载期间只禁用重复导出，不阻塞搜索、翻页或页面导航。切离历史页不取消用户已经确认的导出；显式取消、会话失效、退出关闭或相关服务销毁时必须取消下载。任何失败或取消均不得以不完整内容新建或覆盖目标文件，也不得留下临时文件；目标文件原先存在时必须保留原内容。首版不提供独立的导出取消按钮。

### 7.7 黑白名单管理

- **FR-070** 左侧菜单增加“黑白名单管理”。
- **FR-071** 页面包含“白名单”和“黑名单”两个标签页。
- **FR-072** 每个标签页支持车牌搜索、重置、刷新、新增、删除和分页。
- **FR-073** 搜索只对车牌号执行包含匹配，按回车或搜索按钮触发。
- **FR-074** 每页 100 条，按创建时间倒序。
- **FR-075** 表格列为序号、车牌号、备注、创建用户和创建时间。
- **FR-076** 所有已登录用户均可查询、新增和删除，不引入角色权限。
- **FR-077** 新增字段为车牌号和可选备注，名单类型继承当前标签页。
- **FR-078** 车牌基础规范化为去除首尾 Unicode 空白、ASCII `a-z` 转大写、拒绝内部 Unicode 空白、长度 1 至 16 个 Unicode 码点。空白集合固定为 Unicode 类别 `Zs/Zl/Zp`、U+0009 至 U+000D 和 U+0085；搜索关键字使用相同规则但允许规范化后为空。
- **FR-079** 客户端和服务端均执行基础校验，服务端校验为最终依据。
- **FR-080** 同一规范化车牌不能同时存在于黑名单和白名单，也不能在同一名单重复。
- **FR-081** 删除前显示包含车牌号和名单类型的确认对话框。
- **FR-082** 新增或删除的结果为“已生效”或删除“已不存在”后，重新查询最后已提交的当前标签、关键字和页码；结果为“未生效”或“无法确认”时保留原表格。任何结果都不做乐观本地插入或删除。
- **FR-083** 新增或删除请求只有在 10 秒总时限到期时，才按规范化车牌发起一次精确查询核实服务器现状；核实属于同一写操作生命周期，不得重发原 POST 或 DELETE。核实结果按第 8.6 节固定判定为已生效、未生效或无法确认。
- **FR-084** 无法核实写入结果时显示“操作结果无法确认”，未生效时显示对应失败或冲突现状；两者均保留原表格。会话失效、显式取消、对象销毁或旧上下文只使操作静默失效，不得向新会话或已销毁页面发布三态结果。
- **FR-085** 多管理端名单变更不实时推送；进入页面、搜索、翻页、操作成功和手动刷新时查询。
- **FR-086** 首版不支持编辑、批量删除、有效期、车主字段或自动跨名单转移。
- **FR-087** 黑白名单本期只作为配置数据，不参与抬杆决策。

### 7.8 导航和退出

- **FR-090** 主界面使用左侧导航和右侧页面，登录后 `showMaximized()`；顶部使用 `44px` Qt 自绘标题栏，背景从 `#2A5B78` 到 `#3C7898` 横向渐变，标题文字为纯白，并保留最小化、最大化/还原、关闭、拖动和普通状态缩放能力。
- **FR-091** 左侧依次显示实时监控、置灰的视频识别、置灰的摄像头识别、日志记录、黑白名单管理。
- **FR-092** 左侧底部显示默认头像、用户名、退出登录、HTTP 状态、MQTT 状态、版本和构建日期。
- **FR-093** 点击退出登录时取消网络请求、停止心跳、断开 MQTT、清理内存数据并返回登录页。
- **FR-094** 关闭窗口执行相同清理后退出，不最小化到托盘。
- **FR-095** 退出后的网络回调不得更新登录页或已销毁主窗口。

## 8. HTTP 接口契约

### 8.1 统一信封

除图片和 CSV 二进制响应外，请求和响应均使用 UTF-8 JSON，响应 `Content-Type` 为 `application/json`。客户端接受的单个 JSON 响应体上限为 2 MiB（`2 * 1024 * 1024` 字节）；有 `Content-Length` 时先行检查，接收过程中按解码后的累计响应体字节数再次检查，恰好边界允许，超过 1 字节立即终止请求。

JSON 响应统一使用以下信封，所有字段必须存在且类型固定：

```json
{
  "success": true,
  "code": "OK",
  "message": "",
  "requestId": "request-uuid",
  "data": {}
}
```

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `success` | boolean | 否 | 成功为 `true`，失败为 `false` |
| `code` | string | 否 | 稳定的业务结果码 |
| `message` | string | 否 | 可展示信息；无内容时为空字符串 |
| `requestId` | string | 否 | 服务端生成的请求追踪标识 |
| `data` | object/null | 是 | 成功时按接口返回指定 DTO；无返回数据或失败时为 `null` |

HTTP 成功状态必须同时满足 2xx、`success=true` 和符合对应 DTO 的 `data`。HTTP 错误状态使用 `success=false` 且 `data=null`；客户端不得只依据 HTTP 状态或 `success` 单项判定成功。

统一信封及本章定义的所有 JSON DTO 只允许出现已列出的字段，客户端必须拒绝未知字段。JSON integer 只有在有限、无小数且可由 Qt JSON 无损表示时才可作为 64 位整数接受；绝对值超过 `2^53-1` 的 JSON number 必须拒绝，不能静默舍入。

### 8.2 登录

`POST /api/v1/auth/login`

请求 DTO：

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `username` | string | 否 | 不得为空 |
| `password` | string | 否 | 不得为空 |
| `clientId` | string | 否 | UUID 字符串 |

成功响应的 `data` 必须精确包含以下字段，字段均不可为空：

```json
{
  "displayName": "操作员",
  "accessToken": "access-token",
  "expiresAt": "2026-08-11T18:00:00+08:00",
  "mqtt": {
    "host": "127.0.0.1",
    "port": 8883,
    "tls": true,
    "username": "mqtt-user",
    "password": "mqtt-password",
    "expiresAt": "2026-08-11T18:00:00+08:00",
    "eventTopic": "plate/management/recognition-events"
  }
}
```

字段类型为：`displayName`、`accessToken`、`expiresAt`、`mqtt.host`、`mqtt.username`、`mqtt.password`、`mqtt.expiresAt` 和 `mqtt.eventTopic` 是 string，`mqtt.port` 是 1 至 65535 的 integer，`mqtt.tls` 是 boolean。两个 `expiresAt` 必须是同一 ISO 8601 北京时间值。

登录响应解析得到的会话代次初始为 `0`；实际正数 `sessionGeneration` 由客户端会话服务在建立新登录会话时分配。
代次 `0` 只允许用于未登录状态下的登录请求上下文；一旦建立会话，该上下文立即失效。已经到期的登录响应不得建立会话。

### 8.3 心跳和注销

- `POST /api/v1/clients/heartbeat`：Bearer Token；统一信封只用于响应，请求体为 `{ "clientId": string, "appVersion": string }`，两个字段均必填且不可为空；成功响应的信封 `data=null`。
- `POST /api/v1/auth/logout`：Bearer Token；成功响应的信封 `data=null`；网络失败或超时时允许客户端完成本地退出。

认证接口的 4xx/5xx 响应也必须严格符合失败统一信封。业务 HTTP 401 必须携带原请求的会话代次交给会话服务；只有当前代次的首次 401 触发会话失效，重复或旧代次通知忽略。注销请求在清理前把当前 Token 移交给异步传输层，随后立即清理本地会话，不等待注销结果。

### 8.4 识别记录

- `GET /api/v1/recognitions/{recognitionId}`：查询单条记录，用于 MQTT 重连后的当前记录校准；成功响应 `data` 为一个 `RecognitionSnapshot`。
- `GET /api/v1/recognitions/{recognitionId}/image`：下载 JPEG/PNG 图片。
- `GET /api/v1/recognitions`：参数为 string 类型且固定带 `+08:00` 的 `startTime`、`endTime`、可选 `deviceId`，以及 integer 类型的 `page`、`pageSize`；`startTime` 必须早于 `endTime`，筛选采用 `[startTime, endTime)` 半开区间。`deviceId` 是自由文本，客户端提交时去除首尾空白，结果为空则省略该参数。`page` 从 1 开始且 `pageSize` 固定为 100；成功响应 `data` 为 `PageResult<RecognitionSnapshot>`。
- `GET /api/v1/recognitions/export`：使用相同筛选条件，返回 UTF-8 BOM CSV。

`RecognitionSnapshot` 与 MQTT 事件使用相同 DTO，字段定义如下：

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `schemaVersion` | integer | 否 | 首版固定为 1 |
| `recognitionId` | string | 否 | 识别记录唯一标识 |
| `revision` | integer | 否 | 64 位正整数，同一记录单调递增 |
| `deviceId` | string | 否 | 不得为空 |
| `status` | string | 否 | `PROCESSING`、`SUCCEEDED` 或 `FAILED` |
| `plateNumber` | string/null | 是 | 非空时为规范化车牌，长度 1 至 16 个字符 |
| `errorCode` | string/null | 是 | 稳定错误码 |
| `errorMessage` | string/null | 是 | 最多 512 个字符 |
| `capturedAt` | string | 否 | ISO 8601 北京时间 |
| `startedAt` | string | 否 | ISO 8601 北京时间 |
| `completedAt` | string/null | 是 | ISO 8601 北京时间 |
| `durationMs` | integer/null | 是 | 64 位非负整数，单位毫秒 |

以上字段均必须存在；标记为可空的字段在无值时必须显式为 JSON `null`，不得省略。`recognitionId`、`deviceId` 以及非空状态下的 `plateNumber`、`errorCode`、`errorMessage` 不得是空字符串。

状态与可空字段必须满足：

| 状态 | `plateNumber` | `errorCode` / `errorMessage` | `completedAt` / `durationMs` |
| --- | --- | --- | --- |
| `PROCESSING` | `null` | 均为 `null` | 均为 `null` |
| `SUCCEEDED` | 非空 | 均为 `null` | 均非空 |
| `FAILED` | `null` | 均非空 | 均非空 |

分页 DTO 固定为：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 100,
  "total": 0
}
```

`items` 是对应 DTO 数组，`page` 是从 1 开始的 integer，`pageSize` 首版固定为 100，`total` 是 64 位非负 integer。历史查询响应中的 `page` 必须与原请求 `page` 完全相同；不相同时客户端按协议错误处理，不更新表格、总数或分页状态。

图片响应的 `Content-Type` 去除首尾 ASCII 空白后按 ASCII 大小写不敏感匹配，只接受不带参数的精确媒体类型 `image/jpeg` 或 `image/png`；缺失、带参数或其他类型均拒绝。`QImageReader` 探测的实际格式只允许 JPEG/PNG，`jpg` 归一为 `jpeg` 后必须与声明媒体类型一致。压缩响应体最大接受 20 MiB（`20 * 1024 * 1024` 字节），恰好边界允许。客户端必须在后台线程通过 `QImageReader::size()` 预检宽高，要求宽和高分别不超过 8192 像素且使用 64 位乘法计算的乘积不超过 4000 万；解码为 `QImage` 后必须再次校验实际尺寸。`QPixmap` 只能在 UI 线程创建。

CSV 导出请求只携带与历史页最后已提交筛选快照相同的 string 类型 `startTime`、`endTime` 和可选 `deviceId`，不得携带 `page` 或 `pageSize`。响应只能包含唯一一个语义精确为 `text/csv; charset=utf-8` 的 `Content-Type`；媒体类型、参数名和值按 ASCII 大小写不敏感匹配，分号和参数两侧的可选 ASCII 空白可归一，但重复头、重复或未知参数以及非 `utf-8` 字符集均拒绝。文件必须以字节 `EF BB BF` 开始，首行随后必须精确为 `记录ID,设备,车牌号,状态,错误码,错误信息,拍摄时间,开始时间,完成时间,耗时(ms)` 并以 CRLF 结束。客户端只允许为上述 BOM 和固定首行保留有界小缓冲，正文必须逐块转发和写入，不得累计完整 CSV。CSV 不受 2 MiB JSON 响应上限约束；其 4xx/5xx 响应仍必须是受 2 MiB 限制的严格 JSON 失败信封。

### 8.5 黑白名单

- `GET /api/v1/access-lists?listType=WHITE&keyword=&page=1&pageSize=100`：成功响应 `data` 为 `PageResult<AccessListRecord>`。
- `GET /api/v1/access-lists/lookup?plateNumber=...`：找到时 `data` 为一个 `AccessListRecord`，未找到时返回 HTTP 404。
- `POST /api/v1/access-lists`：成功响应 `data` 为新建的完整 `AccessListRecord`。
- `DELETE /api/v1/access-lists/{id}`：`id` 是 64 位正整数，成功响应 `data=null`。

新增请求：

```json
{
  "listType": "WHITE",
  "plateNumber": "京A12345",
  "remark": "教学测试车辆"
}
```

名单记录：

```json
{
  "id": 1,
  "listType": "WHITE",
  "plateNumber": "京A12345",
  "remark": "教学测试车辆",
  "createdBy": "operator",
  "createdAt": "2026-08-11T11:00:00+08:00"
}
```

`AccessListRecord` 字段规则如下：

| 字段 | JSON 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `id` | integer | 否 | 64 位正整数 |
| `listType` | string | 否 | `WHITE` 或 `BLACK` |
| `plateNumber` | string | 否 | 规范化车牌，长度 1 至 16 个 Unicode 码点 |
| `remark` | string | 否 | 可为空字符串，最多 200 个 Unicode 码点，不使用 `null` |
| `createdBy` | string | 否 | 创建用户显示值 |
| `createdAt` | string | 否 | ISO 8601 北京时间 |

以上字段均必须存在。新增请求中的 `remark` 字段也必须存在，用户未填写时发送空字符串。

客户端只接受已经规范化的名单车牌：去除首尾 Unicode 空白后必须保持不变，不得含内部 Unicode 空白，ASCII 英文字母必须为大写，长度为 1 至 16 个 Unicode 码点；协议解析只校验、不执行规范化转换。Unicode 空白集合固定为类别 `Zs/Zl/Zp`、U+0009 至 U+000D 和 U+0085。`createdBy` 不得为空。

同一规范化车牌冲突返回 HTTP 409，且稳定错误码只能为 `ACCESS_LIST_CONFLICT_WHITE` 或 `ACCESS_LIST_CONFLICT_BLACK`；客户端据此保留现有名单类型，未知 409 错误码按协议错误处理。记录不存在返回 HTTP 404 `ACCESS_LIST_NOT_FOUND`；权限或会话问题返回 HTTP 401/403。

名单 API 和业务服务使用以下固定异步语义：

- 分页查询响应的 `page` 必须等于请求页码，且每个 `items` 记录的 `listType` 必须等于请求类型，否则按协议错误处理。查询失败保留最后成功页。
- 精确查询的 HTTP 404 在 `AccessListApiClient` 层始终是 `NotFound` 错误。普通调用不得把它改写为成功；只有处于名单写超时核实上下文的 `AccessListService` 才按下述判定将其转换为确定业务结果。
- 查询通道与唯一写通道可以并行，各自使用独立递增的请求代次、活动句柄和不可变快照。新的分页查询取消旧分页查询；查询不得取消或替换写请求及其核实请求，写结果也不得直接改写查询结果。
- 从 POST/DELETE 发出到可能的精确查询核实完成，始终视为同一个活动写操作。同一时刻最多存在一个活动写操作；第二个写操作立即以 `Busy` 拒绝，不排队，也不得改变活动写操作。
- 每个响应应用前必须同时验证原 `sessionGeneration`、所属通道的 `requestGeneration`、活动请求句柄和不可变查询或写命令快照。标签、关键字、页码、会话、写命令或句柄任一不匹配时静默丢弃。

### 8.6 HTTP 超时和重试

超时从请求发出时开始计算，到完整响应体接收完成为止。每个请求必须使用独立总时限定时器，超时后中止对应 `QNetworkReply`。

传输层使用 JSON 内存、图片内存和 CSV 流式三种响应模式。CSV 只转发数据块且不累计完整成功响应；各模式的 4xx/5xx JSON 错误信封均按 2 MiB 限制缓冲。客户端禁止自动跟随 HTTP 重定向，显式取消只产生一次取消结果，旧 `RequestContext` 响应只产生失效结果且不得触发业务成功回调。基础传输层不执行任何自动重试。

| 请求 | 总时限 | 自动重试策略 |
| --- | ---: | --- |
| 登录 | 10 秒 | 不重试，由用户重新提交 |
| 注销 | 5 秒 | 不重试，超时后继续本地退出 |
| 心跳 | 5 秒 | 不立即重试，等待下一个 30 秒周期 |
| 识别详情、历史、名单分页和精确查询 | 10 秒 | 不重试，由用户重试；重连校准按下述规则处理 |
| 图片下载 | 每次尝试 30 秒 | 连接失败、超时或 HTTP 500/502/503/504 时，等待 1 秒和 3 秒重试，共最多 3 次请求；手动重试建立新的最多 3 次请求系列 |
| 名单新增、删除 | 10 秒 | 不重复写入；超时后使用精确查询核实服务器状态 |
| CSV 下载 | 120 秒 | 不重试，由用户重新导出 |

MQTT 重连后的当前记录校准失败时保留现状；HTTP 状态以后从“异常”恢复为“在线”时，如果当前记录仍为 `PROCESSING`，只补偿查询一次。除图片下载外，不得对 GET 请求执行隐式循环重试。

历史查询建立新请求前取消旧请求，并使用原请求的 `sessionGeneration`、递增 `requestGeneration`、活动请求句柄和不可变筛选快照共同校验完成结果。切离历史页、会话失效或相关对象销毁时取消在途历史请求；取消和旧上下文失效不显示页面错误，其他失败显示非阻断错误并保留最后成功的表格和分页状态。

名单写操作的确定结果固定为 `Applied`、`AlreadyAbsent`、`NotApplied` 和 `Unknown`，其中 `AlreadyAbsent` 是直接删除返回 404 时的已生效子类；`Unknown` 对应用户文案“操作结果无法确认”。判定规则如下：

| 写操作场景 | 精确查询结果 | 业务结果 |
| --- | --- | --- |
| 新增直接成功 | 不核实 | `Applied` |
| 新增超时 | 返回同一规范化车牌且名单类型与目标相同 | `Applied` |
| 新增超时 | 404，或返回同一车牌但名单类型与目标不同 | `NotApplied`；异类型结果同时保留服务端现有类型 |
| 删除直接成功 | 不核实 | `Applied` |
| 删除直接返回 404 | 不核实 | `AlreadyAbsent`，按已生效处理 |
| 删除超时 | 404，或返回同一车牌但记录 ID 与待删除 ID 不同 | `Applied`；不同 ID 表示目标记录已不存在，随后可能已有并发重建 |
| 删除超时 | 返回的记录 ID 与待删除 ID 相同 | `NotApplied` |
| 新增或删除超时 | 核实发生 403、其他 4xx、5xx、网络、TLS、再次超时或协议错误 | `Unknown` |

仅原写请求的 `Timeout` 触发一次精确查询核实；其他原写失败不触发核实。核实继续占用唯一写通道，且不得重发原写请求。只有 `Applied` 或 `AlreadyAbsent` 才重新提交一次当前最后已提交的标签、关键字和页码查询；`NotApplied`、`Unknown` 和 `Busy` 保留表格。直接 409 作为确定冲突失败并携带稳定现有名单类型，不进入超时三态核实。

当前会话的任何名单请求返回 401 时，API 仍先通知 `SessionService` 统一使会话失效。显式取消、会话失效、服务析构以及 `Cancelled`/`StaleResponse` 回调必须取消查询、原写或核实句柄并静默失效，不发布 `Unknown` 或其他结果给新会话；403 不使会话失效。服务销毁和会话切换后，即使底层回调晚到也不得访问已销毁对象或更新数据。

CSV 保存对话框确认后，客户端必须先成功打开禁用 direct-write fallback 的 `QSaveFile`，再发出导出请求。网络数据块直接增量写入该文件；原子 `commit()` 前必须同时验证当前 `sessionGeneration`、活动 `requestGeneration`、活动请求句柄和不可变筛选快照。CSV 不自动重试。写入、协议、网络、TLS、超时或 `commit()` 失败，以及显式取消、会话失效、退出关闭或服务销毁时，必须调用取消写入并清理临时文件；原目标不存在时不得产生目标文件，原目标存在时不得改变其内容。切离历史页不取消已确认的导出，旧回调仍必须经过上述上下文校验后才能提交。

图片加载以一次用户可见加载或手动重试为一个逻辑请求系列。新的逻辑系列、显式取消、会话失效或图片服务销毁时，必须取消当前 `QNetworkReply` 和尚未触发的重试定时器。已经在线程池运行的预检或解码任务不要求强制终止，但其结果返回 UI 线程前必须同时复核 `sessionGeneration`、逻辑图片 `requestGeneration` 和 `recognitionId`；任一不匹配即丢弃。图片请求必须设置为始终从网络获取且禁止保存缓存，生产代码不得为图片创建 `QNetworkDiskCache`。

## 9. MQTT 事件契约

管理事件主题由登录响应下发，Mock 默认使用 `plate/management/recognition-events`。

事件示例：

```json
{
  "schemaVersion": 1,
  "recognitionId": "recognition-uuid",
  "revision": 1,
  "deviceId": "device-001",
  "status": "PROCESSING",
  "plateNumber": null,
  "errorCode": null,
  "errorMessage": null,
  "capturedAt": "2026-08-11T11:00:00+08:00",
  "startedAt": "2026-08-11T11:00:01+08:00",
  "completedAt": null,
  "durationMs": null
}
```

- 第一次事件为 `PROCESSING`。
- 最终事件为 `SUCCEEDED` 或 `FAILED`，并使用更高 revision。
- 成功填写 `plateNumber`；失败填写稳定 `errorCode` 和可读 `errorMessage`。
- 最终事件仍携带全部字段，不依赖此前事件。
- MQTT 只有在 TCP/TLS 连接、MQTT CONNECT 和主题订阅全部成功后才进入“已连接”。
- 网络中断和 Broker 暂不可用属于暂时错误，按 FR-033 重连。
- 用户名或密码错误、无权限、Client ID 被拒绝、协议不支持、订阅失败和 TLS 证书错误属于永久错误，按 FR-038 至 FR-039 停止当前会话的自动重连并显示原因。

## 10. 本地数据和日志

- 引导配置位于程序旁 `config/client.json`。
- 上次用户名使用 `QSettings`。
- 技术日志位于 `QStandardPaths::AppLocalDataLocation/logs`，采用 UTF-8 JSON Lines，文件名为 `plate-client-YYYY-MM-DD.log`。
- 每行固定包含 `timestamp`、`level`、`module`、`errorCode`、`requestId`、可选 `recognitionId` 和 `context`。
- 技术日志按本地日期生成；启动时只删除日志日期早于“当前本地日期减 7 天”的上述固定文件，恰好 7 天前的日志保留，其他文件不处理。
- 日志按敏感键名和文本模式统一脱敏 Authorization/Bearer、密码、访问令牌、通用 Token 和 MQTT 密码，不得记录完整 HTTP/MQTT 响应、完整 MQTT 载荷、完整图片内容或其他敏感响应。
- 不创建 SQLite 数据库，不直接连接 MySQL，不保存车辆图片或业务历史。

## 11. 异步和安全要求

- **NFR-010** 所有 HTTP/MQTT 操作必须异步。
- **NFR-011** 每次登录使用会话代次，每次页面查询使用请求代次。
- **NFR-012** 响应只有在会话、页面条件和业务对象仍匹配时才能更新 UI。
- **NFR-013** 图片尺寸预检和 `QImage` 解码必须在线程池执行，CSV 文件收尾不得长时间阻塞 UI；`QPixmap` 和 QWidget 只能在 UI 线程访问。
- **NFR-014** 密码、访问令牌和 MQTT 凭据只驻留内存。
- **NFR-015** 不得静默忽略 TLS 证书错误。
- **NFR-016** 单个 JSON 响应体最大 2 MiB，图片压缩响应体最大 20 MiB，图片宽高分别最大 8192 像素且总像素最大 4000 万；名单备注最大 200 个字符，识别错误信息最大 512 个字符。

## 12. 已确认限制

- 实时首页不是历史数据来源，只显示本次登录期间事件。
- MQTT 重连只校准当前 `PROCESSING` 记录，不补齐其他事件。
- 完整记录需要用户进入日志页查询。
- HTTP 状态只表示网络可访问。
- 名单变更不实时同步到其他 Qt 客户端。
- 名单不参与当前抬杆规则。
